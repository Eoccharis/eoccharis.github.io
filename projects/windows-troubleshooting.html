PERSONAL TECHNICAL CASE · AUGUST 2026

Windows 11 troubleshooting, recovery & reinstallation

A practical troubleshooting case involving an unexpected Windows recovery environment, boot-configuration issues, data preservation, storage-driver troubleshooting and a clean Windows 11 installation.

Environment HP Victus 16-d0033nia
Operating System Windows 11 Home
Storage ~1 TB Samsung NVMe SSD
Incident Date 19 August 2026

01 / OVERVIEW

Restore a usable system without compromising the user's data.

During preparation of the laptop for virtualization and Windows configuration work, the system restarted unexpectedly and began entering a Windows recovery environment instead of the expected Windows desktop.

The recovery screen referenced a "Windows Server" environment that did not match the expected installation. The display behaviour was also abnormal, creating uncertainty about whether the original Windows environment and user data were still intact.

The first objective was therefore not to reinstall Windows immediately. The priority was to establish what was still present, protect user data and determine the safest recovery path.

02 / INITIAL SYMPTOMS

01

Unexpected recovery environment

The laptop repeatedly booted into a recovery-style environment rather than the normal Windows desktop.

02

Unexpected boot entry

The recovery interface offered an option to continue to "Windows Server", which did not match the expected operating system.

03

Display problems

The built-in display was initially/intermittently blank and an external display was not behaving as expected.

04

Data-loss risk

The system contained important personal, course and IT-lab files, so destructive remediation could not be performed without first protecting the data.

03 / DIAGNOSIS

Disk Management

Disk Management confirmed that the internal SSD was present and online. The disk contained an EFI system partition, a large Windows partition and a recovery partition.

Key finding The internal storage had not simply disappeared or become physically disconnected.

Windows.old

A large C:\Windows.old directory was discovered, including a preserved user profile and personal data.

Key finding Significant user data remained recoverable before reinstalling.

BCDEdit investigation

Boot configuration data was inspected from the Windows Recovery Command Prompt. The default Windows boot-loader entry pointed to the Windows installation on the C: partition but was labelled "Windows Server".

Key finding The boot state was inconsistent with the expected Windows environment.

04 / DATA PROTECTION

Protect the data before making destructive changes.

01

Identify recoverable data

Located the preserved user profile and important personal folders inside the previous Windows installation.

02

Create an external backup

Copied important files to an external drive rather than moving them, retaining the original backup as a fallback.

03

Verify the recovery path

Kept the backup available until the replacement Windows installation had been validated.

05 / STORAGE DRIVER TROUBLESHOOTING

The installation could not see the internal SSD.

After creating Windows 11 installation media, Windows Setup could detect the installation USB but could not enumerate the internal Samsung NVMe SSD.

Instead of assuming the SSD had failed, the exact HP laptop model was identified and the vendor's Intel Rapid Storage Technology package was investigated.

Driver identified Intel Rapid Storage Technology / VMD F6 driver HP SoftPaq SP147234 · Version 19.5.2.1049

The extracted F6 driver was loaded into Windows Setup. Immediately afterward, the internal SSD became visible as the installation target.

This provided strong evidence that the installation-time storage visibility problem was caused by the missing Intel RST/VMD driver, rather than the SSD being physically absent.

06 / REMEDIATION

Clean installation and controlled post-install validation.

01 Identify the correct target disk

Confirmed the internal SSD separately from the Windows installation and driver USB devices.

02 Remove the previous Windows partitions

After the user data had been backed up, the previous Windows, MSR and recovery partitions were removed.

03 Install Windows 11 Home Single Language

Windows was installed to the resulting unallocated space.

04 Run Windows Update

Driver and firmware updates were applied to restore expected hardware functionality.

05 Validate Device Manager

Graphics, audio and other core devices were checked for missing or faulty drivers.

06 Restore personal files

Important files were copied from the external backup after the new system had been validated.

07 / OUTCOME

The system was returned to a stable working state.

Validation was performed against practical acceptance criteria rather than assuming that a successful Windows installation alone meant the incident was resolved.

PASS Windows 11 installation

Fresh Windows 11 Home installation completed successfully.

PASS Internal SSD

SSD became visible after loading the correct RST/VMD driver.

PASS Wi-Fi & touchpad

Core input and network functionality were restored.

PASS Graphics & audio

Expected Intel, NVIDIA and Realtek devices were present without visible warning symbols.

PASS Windows Update

Required driver and firmware updates were applied successfully.

PASS Personal data

Backed-up personal files were restored to the new Windows environment.

08 / ROOT-CAUSE ANALYSIS

Separate what was proven from what was probable.

The immediate technical blocker during Windows installation was identified with high confidence: the Windows Setup environment lacked the Intel RST/VMD storage driver required to enumerate the internal NVMe SSD.

The original boot incident was different. The available evidence indicated an inconsistent boot configuration or OS state, but the exact event that changed that state could not be conclusively established.

Key troubleshooting principle Do not convert an informed hypothesis into a confirmed root cause. Record what the evidence proves, what it suggests and what remains unknown.

09 / LESSONS LEARNED

A reusable troubleshooting workflow, not just a one-off fix.

01

Start with read-only diagnostics before making destructive changes.

02

Identify and protect recoverable user data before reinstalling an operating system.

03

Match vendor drivers to the exact hardware model when dealing with storage-controller problems.

04

Distinguish installation media, driver media and the internal target disk carefully.

05

Validate hardware and drivers before rebuilding applications or virtual machines.

06

Keep the original backup until the replacement system and restored files have been verified.
